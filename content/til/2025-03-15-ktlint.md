## ktlint란?

Kotlin 코드 스타일을 검사하고 자동으로 포맷해주는 린터.
`.editorconfig` 설정을 통해 규칙을 커스터마이징할 수 있고, 없으면 기본 규칙이 적용된다.

## 설정 위치

**`build.gradle.kts` (루트)**
```kotlin
ktlint {
    version.set(Version.ktLintTool)
    filter {
        exclude { it.file.path.contains("/build/") }
    }
}
```

**`buildSrc/src/main/kotlin/Version.kt`**
```kotlin
const val ktLintTool = "1.7.1"
```

## 주요 명령어

```bash
# 스타일 위반 검사
./gradlew ktlintCheck

# 자동 포맷 (수정 가능한 항목만)
./gradlew ktlintFormat
```

## 자동 수정 가능한 규칙들

- import 알파벳 순 정렬
- 불필요한 빈 줄 제거 (연속 2줄 이상)
- 들여쓰기 (space 4칸)
- 줄 끝 공백 제거
- 파일 끝 개행 추가
- `{` 앞 공백, `:` 뒤 공백 등 spacing

## .editorconfig로 규칙 커스터마이징

ktlint는 프로젝트 루트의 `.editorconfig` 파일을 읽어 규칙을 조정할 수 있다.

```ini
# .editorconfig
root = true

[*.{kt,kts}]
indent_size = 4
max_line_length = 120

# 특정 규칙 비활성화
ktlint_standard_no-wildcard-imports = disabled

# import 정렬 레이아웃 커스텀
ktlint_standard_import-ordering = disabled
```

`.editorconfig`가 없으면 ktlint 기본값이 적용된다. 팀 컨벤션이 기본값과 다르다면 이 파일로 명시적으로 관리하는 게 좋다.

## pre-commit hook 연동

`git commit` 시 자동으로 ktlintFormat → ktlintCheck 순서로 실행되도록 Claude Code hook 설정.

동작 순서:
1. `git commit` 시도
2. hook이 `ktlintFormat` 실행 → 파일 자동 수정
3. 수정된 파일이 있으면 커밋 차단 + 변경 파일 목록 출력
4. `git add` 후 재시도하면 `ktlintCheck` 통과 → 커밋 성공

## ktlint의 한계: same-package import

Kotlin에서는 **같은 패키지에 있는 클래스는 import 없이도 자동으로 참조**된다.
하지만 ktlint는 이 불필요한 import를 감지하지 못한다.

**예시 — `BusinessPartnerService.kt`**

```kotlin
package com.example.service          // 이 파일의 패키지

import com.example.service.ShopInfo  // ← 같은 패키지, 불필요한 import
import com.example.other.SomeClass   // ← 다른 패키지, 필요한 import

class BusinessPartnerService {
    fun process(info: ShopInfo) {    // ShopInfo는 같은 패키지라 import 없어도 됨
        // ...
    }
}
```

ktlint 입장에서는 `ShopInfo`가 코드에서 실제로 **사용되고 있으므로** "unused import"로 판단하지 않는다.
같은 패키지라서 import가 불필요하다는 사실은 체크하지 않는 것이다.

**결과:** `ktlintFormat`을 돌려도 이 import는 그대로 남는다.

**해결 방법:** IntelliJ에서 `Cmd+Alt+O` (Optimize Imports) 로 수동 정리
