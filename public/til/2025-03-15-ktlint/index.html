ktlint란?#

Kotlin 코드 스타일을 검사하고 자동으로 포맷해주는 린터. .editorconfig 없이도 기본 규칙만으로 일관된 코드 스타일을 유지할 수 있다.

설정 위치#

프로젝트에서 두 곳에서 관리된다.

build.gradle.kts (루트)

ktlint {
    version.set(Version.ktLintTool)
    filter {
        exclude { it.file.path.contains("/build/") }
    }
}

buildSrc/src/main/kotlin/Version.kt

const val ktLintTool = "1.7.1"

주요 명령어#

# 스타일 위반 검사
./gradlew ktlintCheck

# 자동 포맷 (수정 가능한 항목만)
./gradlew ktlintFormat

자동 수정 가능한 규칙들#

  • import 알파벳 순 정렬
  • 불필요한 빈 줄 제거 (연속 2줄 이상)
  • 들여쓰기 (space 4칸)
  • 줄 끝 공백 제거
  • 파일 끝 개행 추가
  • { 앞 공백, : 뒤 공백 등 spacing

pre-commit hook 연동#

git commit 시 자동으로 ktlintFormat → ktlintCheck 순서로 실행되도록 Claude Code hook 설정.

# .claude/hooks/ktlint-pre-commit.sh
# git commit 명령어 감지 → ktlintFormat 실행 → 변경사항 있으면 커밋 차단

동작 순서:

  1. git commit 시도
  2. hook이 ktlintFormat 실행 → 파일 자동 수정
  3. 수정된 파일이 있으면 커밋 차단 + 변경 파일 목록 출력
  4. git add 후 재시도하면 ktlintCheck 통과 → 커밋 성공

ktlint의 한계#

same-package import는 잡지 못한다.

package com.example.service

import com.example.service.SomeClass  // ← 같은 패키지, 불필요한 import

SomeClass가 코드에서 실제로 사용되고 있으면 ktlint는 이를 “사용 중인 import"로 판단해 제거하지 않는다. 같은 패키지의 클래스는 import 없이도 자동 참조 가능하므로 이 import는 불필요하지만, ktlint 표준 규칙에는 해당 케이스가 없다.

해결 방법: IntelliJ에서 Cmd+Alt+O (Optimize Imports)
